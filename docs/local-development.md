# Local development

How to run Lootlark (the GameStore code) on your own machine, how the local services fit together and how to fix the common problems. The project is not deployed anywhere; everything here runs locally. New to a tool mentioned here? See the [glossary](glossary.md). For the design behind it see [architecture.md](architecture.md).

## Prerequisites

| Need | Why |
| --- | --- |
| [.NET SDK](https://dotnet.microsoft.com/en-us/download) 8.0 or newer | The projects target `net8.0`. The Aspire packages come from NuGet, so no `aspire` workload is needed. |
| [Docker Desktop](https://www.docker.com/products/docker-desktop/), running | The AppHost starts PostgreSQL, pgAdmin, Azurite, the Service Bus emulator, Keycloak and the Stripe CLI as containers; the integration tests use Testcontainers. |
| [Node.js](https://nodejs.org/) 22 | The version is pinned in [`.nvmrc`](../.nvmrc) (`nvm use` picks it up). |
| A [Stripe](https://dashboard.stripe.com) account in **test mode** | A secret key (`sk_test_...`) for the backend and a publishable key (`pk_test_...`) for the front end. Never use live keys. |

## Secrets and parameters

The AppHost (`backend/src/GameStore.AppHost/AppHost.cs`) declares four parameters. Defaults or placeholders are in `backend/src/GameStore.AppHost/appsettings.json`; real values go in .NET user-secrets, which live in your user profile and are never committed.

| Parameter | Committed value | What to do |
| --- | --- | --- |
| `StripeApiKey` (secret) | none | Required. Your Stripe test secret key. It is passed to the API as `Stripe__SecretKey` and to the two Stripe CLI containers. |
| `EntraAuthority` | `[ENTRA AUTHORITY HERE]` | Required even when you only use Keycloak (see below). |
| `EntraValidAudience` | `[ENTRA VALID AUDIENCE HERE]` | Only matters when you sign in with Entra. |
| `CheckoutReturnUrl` | `http://localhost:5173/order-created` | Keep it; Stripe sends the browser back here after payment. |

```bash
# Stripe test secret key (sk_test_ only)
dotnet user-secrets set "Parameters:StripeApiKey" "sk_test_..." --project backend/src/GameStore.AppHost

# The API refuses a non-HTTPS authority: with the placeholder, every request (even GET /games)
# returns 500 ("The MetadataAddress or Authority must use HTTPS"). Locally Keycloak is used,
# so any HTTPS authority such as this one is enough:
dotnet user-secrets set "Parameters:EntraAuthority" "https://login.microsoftonline.com/common/v2.0" --project backend/src/GameStore.AppHost
```

Passwords for PostgreSQL, Keycloak and the Service Bus emulator are generated by Aspire on the first run and saved to the same user-secrets store (for example `Parameters:postgres-password` and `Parameters:keycloak-password`). List everything with `dotnet user-secrets list --project backend/src/GameStore.AppHost`.

## Start the backend

```bash
dotnet run --project backend/src/GameStore.AppHost --launch-profile http
```

The first run pulls several container images, so it takes a while. Everything appears in the Aspire dashboard.

| Resource | Address | Notes |
| --- | --- | --- |
| Aspire dashboard | http://localhost:15054 | Resource states, logs, traces and metrics for every service. |
| `gamestore-api` | http://localhost:5082 | The ASP.NET Core API. |
| `gamestore-worker` | none | Background worker that consumes the `orders` queue. |
| PostgreSQL 17.4 | `localhost:5432` | Database `gamestore` (connection name `GameStoreDB`). |
| pgAdmin | http://localhost:5050 | Web UI for the database. |
| Azurite 3.34.0 | blobs on `localhost:10000` | Local Blob storage for game images. |
| Service Bus emulator | | Queue `orders` with duplicate detection on. It also starts a SQL Server container. |
| Keycloak 26.0.7 | http://localhost:8080 | Realm `gamestore`, imported from `backend/localinfra/gamestore-realm.json`. |
| `stripeSecretGen` | | Stripe CLI container that writes the webhook signing secret to `backend/.stripe/webhook_secret.txt` (git-ignored) and exits. |
| `stripeListener` | | Stripe CLI container that forwards Stripe test events to `<api>/payments/stripe-webhook`. |

The API waits for PostgreSQL, Azurite, the Service Bus emulator, Keycloak, the Stripe listener and for `stripeSecretGen` to finish. The AppHost reads the secret file and gives it to the API, so a missing or invalid Stripe key stops the API from starting.

The health endpoints `/health/ready` and `/health/alive` answer only when the request host is exactly `localhost:5082` or any host on port 8081:

```bash
curl http://localhost:5082/health/ready
curl http://localhost:5082/health/alive
```

Other hosts, such as `https://localhost:7077` from the API's own `https` launch profile, get a 404 for these two paths.

## Create a Keycloak user

The imported realm already contains everything the app needs except users: the `gamestore-api` audience, the `gamestore_api.all` scope (with the audience mapper), the role claim mapper, the `gamestore-frontend-react` client for the front end (redirect `http://localhost:5173/authentication/callback`), a `postman` client and the `Admin` realm role.

1. Open http://localhost:8080 and sign in as `admin`. The password is the `Parameters:keycloak-password` user secret.
2. Switch to the realm `gamestore`.
3. Users > Add user. Fill in a username, set **Email verified** on and create it.
4. Credentials > Set password, with **Temporary** off.
5. Role mapping > Assign role > `Admin`, if this user should be able to create, edit and delete games.

## Start the front end

```bash
cd frontend
cp .env.example .env.local   # then set VITE_STRIPE_PUBLISHABLE_KEY=pk_test_...
npm ci
npm run dev
```

[`frontend/.env.example`](../frontend/.env.example) lists every `VITE_*` setting with local defaults: the API on http://localhost:5082, `VITE_IDENTITY_PROVIDER=keycloak` and the Keycloak realm started by the AppHost. `.env.local` is git-ignored. `VITE_*` values are baked into the browser bundle, so never put a secret in them; the Stripe publishable key is public by design.

The dev server listens on http://localhost:5173 unless the `VITE_PORT` environment variable is set (see `frontend/vite.config.ts`). Keep 5173: the Keycloak client's redirect URI and `CheckoutReturnUrl` point at it. In Development the API accepts requests from any origin, so CORS needs no change.

Other scripts: `npm run lint` (ESLint), `npm run build` (type check and production build into `dist/`) and `npm run preview` (serve that build).

## Try a payment

1. Open http://localhost:5173, sign in with the Keycloak user and add a game to the basket.
2. Check out and pay with Stripe's test card `4242 4242 4242 4242` (any future expiry date, any CVC).
3. Stripe sends `checkout.session.completed`; the `stripeListener` container forwards it to the API, which verifies the signature, marks the order `Processing` and writes an outbox row in the same transaction.
4. Within about ten seconds the outbox processor publishes the message to the `orders` queue, the worker assigns the game codes and the order becomes **Completed**.

Where to look: the order page in the app, the `OutboxMessages` table in pgAdmin, and the API and worker logs in the Aspire dashboard.

The API accepts Stripe events of any API version (`throwOnApiVersionMismatch: false` in `backend/src/GameStore.Api/Shared/Stripe/StripeEventFactory.cs`). This is needed because `stripe listen` forwards events in the test account's default API version, while Stripe.net expects its own pinned version; without it every webhook would be rejected with 400 and orders would stay `Pending`. The signature is still verified.

`stripe trigger checkout.session.completed` (with a locally installed Stripe CLI logged in to the same test account) sends a generic event without an order id, so it does not complete a real order. Pay a session from the front end instead.

## Call the API without the front end

Anonymous endpoints work directly, for example `curl http://localhost:5082/games` and `curl http://localhost:5082/genres`. The full list of endpoints is in [architecture.md](architecture.md#7-api-surface).

For endpoints that need a token, the realm's clients have direct access grants (password sign-in from a script) switched off. To get a token with `curl`, first switch on **Direct access grants** on the `postman` client in the Keycloak admin console (Clients > `postman` > Settings > Capability config), then:

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/realms/gamestore/protocol/openid-connect/token \
  -d grant_type=password -d client_id=postman \
  -d username=<user> -d password=<password> \
  -d scope="openid gamestore_api.all" | jq -r .access_token)

curl -H "Authorization: Bearer $TOKEN" http://localhost:5082/orders
```

This is the standard OpenID Connect token request; it needs `jq`. The admin console change is stored in the Keycloak data volume, not in the repository.

## Using Microsoft Entra ID instead of Keycloak

Keycloak is the local default and needs no Microsoft account. The API also accepts Microsoft Entra ID tokens: a policy scheme picks the Entra scheme when the token issuer contains `ciamlogin.com`, and Keycloak otherwise (Keycloak only in Development). To sign in with Entra locally you need your own Entra external tenant with an API app registration (scope `gamestore_api.all`, app role `Admin`) and a single-page-app registration with the redirect URI `http://localhost:5173/authentication/callback`. Then:

```bash
dotnet user-secrets set "Parameters:EntraValidAudience" "<entra-api-client-id>" --project backend/src/GameStore.AppHost
dotnet user-secrets set "Parameters:EntraAuthority" "https://<tenant-subdomain>.ciamlogin.com/<tenant-id>/v2.0" --project backend/src/GameStore.AppHost
```

In `frontend/.env.local` set `VITE_IDENTITY_PROVIDER=entra` and fill in `VITE_ENTRA_CLIENT_ID`, `VITE_ENTRA_AUTHORITY` and `VITE_ENTRA_SCOPE` (the placeholders in `.env.example` show the shape). Never commit tenant or client ids.

## Stop and clean up

Stop the AppHost with `Ctrl+C`. PostgreSQL, pgAdmin, Azurite, the Service Bus emulator and Keycloak are persistent containers: they keep running after the AppHost stops and keep their data volumes, so the next start is fast and your data survives.

For a clean slate, remove those containers and their volumes in Docker Desktop, or with the Docker CLI. This deletes your local development data only (database, uploaded images, Keycloak users):

```bash
docker ps -a                      # find the GameStore containers (postgres, pgadmin, storage, servicebus, keycloak)
docker rm -f <container-id> ...
docker volume ls                  # Aspire names the data volumes after the AppHost (gamestore.apphost-...)
docker volume rm <volume-name> ...
```

Review both lists before removing anything.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| Every API request returns 500 right after start | `Parameters:EntraAuthority` is still the placeholder. Set it as shown in [Secrets and parameters](#secrets-and-parameters). |
| The API never starts and the dashboard shows `stripeSecretGen` failed | The Stripe key is missing or invalid. Set `Parameters:StripeApiKey` to a `sk_test_` key. |
| PostgreSQL logs `password authentication failed for user "postgres"` (the API stays Waiting), or the Keycloak admin login fails | A data volume was created with a password that is no longer in user-secrets, so Aspire generated a new one. Remove the PostgreSQL or Keycloak container and its volume (see [Stop and clean up](#stop-and-clean-up)) and start again; Aspire then saves the new password. |
| Webhooks return 400 or orders stay `Pending` | Check that the `stripeListener` container is running and that the key is a test key. |
| Sign-in redirects fail | The dev server is not on port 5173, or `.env.local` points at another Keycloak realm or client. |
| Integration tests report zero tests or hang | Docker is not running or is still pulling images. |
